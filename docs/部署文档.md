# 部署文档（2026-11-05 更新）

## 1. 环境要求

- Python 3.10–3.12（实测 3.12.3）
- 内存 ≥ 8GB：训练基数组 958 万行 × 29 特征，不要一次性全读
- 磁盘：`~/workspace/ashare/` 实测 53GB、1345 个文件（2026-11-05 盘点；源码 < 5MB，其余为数据与模型）
- 网络：Yahoo Finance（行情）、新浪行情中心（股票池与市盈率）
- 虚拟环境：`~/workspace/ashare_venv`（主环境）；Kronos 真实推理另需 torch CPU 版（`pip install torch --index-url https://download.pytorch.org/whl/cpu`）


## 4. 现行策略口径（2026-11-02 16:00 用户锁定，三策略统一）

- 买入：信号收盘 × 0.95 限价（x=0.05）；跳空低开按开盘价成交（更优）
- 止盈：+7%（成本 × 1.07）；跳空穿过按开盘价成交
- 止损：仅原策略 −2%；m=2/m=3 无止损
- 费用：0.5% 往返，从实现收益中扣除
- 选股：各策略 Top10；“平均每笔”按前 3 只中成交的统计
- 执行：gap-aware 真实记账；同日双触按止损算（原策略）；名称含“退”/“ST”一律不选
- 中央配置：`strategy_config.py`

三策略：①原策略（HGB 分类器，每日增量重建，T+2 卖出）；②m=2（EV 回归固定模型，最多持有 2 天）；③m=3（EV 回归固定模型，最多持有 3 天）。详见 `strategies_overview.md`、`mday_strategy.md`。

2026-11-05 管道加固后：8 阶段标记（`daily_output/<日>.stages.json`，原子写）、增量标签幂等（库中有该信号日即跳过）、`m_compare.json` counted_keys 防重计、关键落盘原子写、打分模型版本记录（续跑还原原模型）。策略口径未动。

## 8. 常见问题

- **管道退出码为 0 但没产出**：以输出文件存在且可加载为准（`daily_output/<日>.json`、`stages.json`）。
- **datetime64 精度**：pandas 3.x 存 datetime64[s]，日期转整数用 `.values.astype('datetime64[D]').astype(int)`。
- **浮点相等**：止损/止盈计数用价格触碰重算，不用 `realized == -0.02` 精确比较。
- **Yahoo 限流/超时**：下载脚本自带重试与断点，隔段时间重跑 resume 脚本。
- **Kronos 权重下不到**：先检查网络到 HuggingFace；脚本无权重时冒烟用占位信号（summary 标 `kronos_real=false`），全量必须真实权重。
